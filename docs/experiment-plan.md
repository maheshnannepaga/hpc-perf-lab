# Week 1 experiment plan

## Question

How do matrix dimension and cache tile size affect correct C++ GEMM throughput on one CPU core?

## Controls

- Run on an otherwise idle machine.
- Use the same compiler and optimization flags for all runs.
- Record hardware and software details in release notes.
- Use at least three repetitions and report the average.
- Use `--verify` for every configuration while developing.

## Experiment matrix

| Matrix size | Tile sizes | Repetitions | Threads |
| --- | --- | --- | --- |
| 256, 512, 1024 | 16, 32, 64 | 3 | 1 |

## Acceptance criteria

1. Every run reports `verification: PASS`.
2. The raw CSV is generated by a committed script, not edited manually.
3. The README records the environment and a benchmark table.
4. One design decision is documented: the preferred tile size and a reasoned interpretation.

## Week 2 extension

Build with `OPENMP=1`; repeat at 1, 2, 4, and 8 threads. Report speedup and efficiency, and inspect one run with `perf stat`.
